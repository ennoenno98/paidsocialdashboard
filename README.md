# Vanatari Social Dashboard

Python pipeline + Streamlit dashboard for Vanatari's social media KPIs (Vegavero, wowtamins, Jasnum):

1. **Windsor.ai** (primary, `src/ingest/windsor.py`) — Instagram own-account post insights and daily account insights
   (`instagram` connector), Meta boosted posts (`facebook`, campaigns named `Instagram post: …`, mapped to the promoted
   own post by caption prefix → brand/market) and creator public counts (`instagram_public`).
2. **Klar** — creator master (handle, deal type, category, code, followers) and commercials (`influencer_flex`: costs,
   orders, net revenue, ROAS, CAC).
3. **Workbook** — parses the human-formatted `Social_Media.xlsx` for TikTok (not in Windsor yet), history and
   reconciliation (monthly sheet vs Boosting Susy vs Meta Ads).
4. **Paid creatives** — Meta ad-level feed (Windsor `facebook`, `facebook__ads` pull): one row per creative asset
   × funnel stage (prospecting / retargeting) with spend, CTR, CPC, CPM, CPA, ROAS, hook rate, verdicts, controlled
   creative tags and the test log. Replaces the hand-built `Vegavero_Paid_Social_Asset_Tracker.xlsx`.
5. **Dashboard** — Overview (API weekly/monthly or sheet scope, never mixed), Organic vs Boosted, Post performance,
   Influencers, Paid creatives, Data quality.

Metric rules are in [`config/metric_definitions.md`](config/metric_definitions.md). Account mapping in [`config/accounts.yaml`](config/accounts.yaml).

## Data sources and gaps

| Need | Source | Status |
|---|---|---|
| IG own accounts: per-post reach/views/likes/comments/saves/shares/follows, daily reach/views/interactions | Windsor `instagram` | live for all 4 accounts |
| Boosted posts: spend, reach, impressions, clicks per promoted post | Windsor `facebook` | live; 100 % of boost spend maps to a post (caption prefix) |
| Creators: likes/comments/followers per post | Windsor `instagram_public` | live for connected handles; add every Klar handle in Windsor |
| Creator master + commercials | Klar | HTTP client stub until the Public API docs are confirmed; cache/CSV meanwhile |
| TikTok organic + boosted | workbook | `tiktok_organic` not connected in Windsor; TikTok Business API or Studio CSV export as alternatives |
| Budget, pillar/topic tags, creator reach | manual CSV | not in any API |
| Paid creatives: ad × day × ad set with ad set targeting, creative thumbnail, body / title, omni purchases and value, video play curve | Windsor `facebook` (`facebook__ads`, 7-day click / 1-day view) | live for the Vegavero ad account (IT ads only for now); add accounts / markets in `config/creatives.yaml` |
| Paid creatives: Klar-attributed orders and revenue per Meta ad | Klar `marketing_flex` (campaign + content = ad name) | JSON / CSV exports in `data/raw/klar_marketing`; Klar Public API client still a stub |

Period reach from the API is the **sum of daily unique reach** (`reach_daily_sum`) and is labelled as such; it is
not comparable to the sheet's weekly reach. New followers are available for the last 30 days only (Meta), followers
are a daily snapshot that `make refresh` appends to `data/processed/ig_followers_history.parquet`.

## Quick start

```bash
make install                      # uv venv (Python 3.12) + deps
make parse                        # parse workbook -> prints tidy frames + block coverage, writes data/processed/xlsx_*.parquet
make refresh-offline              # full pipeline on cache/fixtures (no API calls)
# with WINDSOR_API_KEY set, `make refresh` (or the app at start-up) pulls Windsor live into data/raw/windsor
make app                          # streamlit run app/Home.py
make test && make lint
```

Put the real workbook at `data/Social_Media.xlsx` (gitignored, contains PII) or set `SOCIAL_XLSX`. Without it everything runs on
`tests/fixtures/Social_Media_fixture.xlsx`, a synthetic workbook that reproduces the real layout and its quirks
(generated by `tests/fixtures/build_fixture.py`); the app shows a yellow **FIXTURE** banner in that case.

## Workbook parsing

Each relevant sheet is scanned for *blocks*: a title row in col A followed by a period header (`CW 01 …` or month names)
in cols B+. Labels are normalised (strip, lower, synonyms: `AD Spent`/`Total Spent`/`Boosting Spent`/`Ad cost` → `boost_spend`,
`Overall` → `net_follows`, …). Cells `/`, `#DIV/0!`, names → NaN. Header gaps (`CW 03, None, CW 04`) are forward-filled
and duplicate period columns aggregated (sum for boosting blocks, first + warning otherwise, text first). Month typos
(`Janury `) are tolerated. Blocks that start in June simply have fewer periods. Post by Post groups are split at each `Post`
label row (one row per account × CW × slot). Orphan cells outside labelled columns are ignored and reported.

Run `make parse` and verify the **block coverage report** (sheet, title, row range, account, periods, metrics, values,
status) against the sheet. Unmapped titles are `unmapped_title` → add them to `config/accounts.yaml`.

Known items to verify on the real file (flagged in the Data quality page):

- `Boosting TikTok` has no account in its title → mapped to `vanatari/tiktok/INT` (`accounts.yaml`, TODO comment).
- `Boosting Susy` budget column: configured as col `E` (`sheets.boosting_susy.budget_col`). If col E carries a month
  label the value is read as spend and a warning is raised.
- 2025 sheets are parsed with the same rules; blocks that do not fit show up as `unparsed`/`unmapped_title`.

**PII:** the Creators address column is never selected, never stored, never logged (`parse_creators` reads whitelisted
headers only). The workbook itself is gitignored.

## Klar

`src/ingest/klar.py` targets the `influencer_flex` report (vocabulary verified against the live schema). Klar's help
center documents a **Public API** (API keys via the "API Key Management" role) and a legacy Attribution API
(`https://api.getklar.com/`, 31-day max range, 2 req/30 s, deprecated 2026-09-30). The technical endpoint spec was not
reachable when this was built, so `HttpKlarClient` raises `NotImplementedError` until `KLAR_INFLUENCER_REPORT_PATH`
(+ `KLAR_API_BASE_URL`, `KLAR_REQUEST_STYLE`) are set from the docs — it never guesses. Meanwhile:

- `FixtureKlarClient` / cached `data/raw/klar/YYYY-MM-DD.json`
- `CsvExportKlarClient` (`KLAR_CSV_EXPORT=path.csv`, a UI export of the report)

Important: Klar's `reach` and `cpm` are **0 for every partnership** in this account, so influencer CPM comes from
`data/manual/influencer_reach.csv` (`handle, post_url, date, reach, source`), filled from creator-provided insights.

## Instagram

- Own accounts: `IG_BUSINESS_ACCOUNT_IDS` (JSON key → id) + `META_ACCESS_TOKEN`; `/{ig-user-id}/media` + `/{media-id}/insights`
  (`reach, saved, shares, total_interactions, views`). Idempotent daily upsert to `data/processed/ig_posts.parquet`.
- Creators: Business Discovery (`followers_count, media_count, media{like_count, comments_count, timestamp}`) →
  `interactions_per_post`, posting cadence. 400s → "not scannable". **No reach for third parties**, hence no followers-based CPM/ER anywhere.
- `WindsorSource` (`WINDSOR_API_KEY`, `instagram_public` connector) is a swappable alternative; field names unverified.

## Design

Charts and the Streamlit theme follow the Vanatari Corporate Design 2026 booklet: plum `#3c1826` text, warm orange
`#ff5c3e` highlights, beige `#fbf7f2` page, light blue `#e3eef6` elements, Satoshi body / Literata headings. The

## Stories, Collab posts and the Klar influencer sheets

- **Stories**: Meta exposes a story for 24 hours, so the `instagram__stories` pull runs daily (`make refresh` /
  the refresh workflow) and accumulates by `story_id` in `data/raw/windsor/instagram__stories.json`. History starts
  with the first daily run. Stories feed `n_stories`, `story_reach_sum`, `story_exit_rate` … in the API periods.
- **Collab posts**: the media pull asks Windsor for `media_relationship=owned,collaborative`, so Instagram Collab
  reels owned by a creator with an own account as co-author are listed (Post performance → "Collab posts",
  Influencers). Meta gives likes/comments/saves/shares but no reach for them, so they never count as own posts and
  their ER stays n/a.
- **Klar influencer Google Sheets** ("Influencer Vegavero", "Influencer Wowtamins", owned by Klar's service
  account) are the campaign master: `Influencer/Affiliate Name` is the handle and the join key to Klar's
  `influencer_name`; `Reach` and `Link to Post` are the columns to fill per campaign. Reach entered there feeds
  Klar's own CPM and this dashboard (`reach_source = klar_sheet`). Cache: `data/raw/klar_sheets/*.csv` (CSV export
  of each sheet); `make refresh` downloads them when `KLAR_SHEET_CSV_URLS` holds published-CSV links
  (`{"vegavero": "https://docs.google.com/spreadsheets/d/<id>/export?format=csv&gid=<gid>", …}`, from
  File → Share → Publish to web). The Data quality page lists paid campaigns still missing reach.

## Paid creatives

The **Paid creatives** dashboard is a **separate Streamlit app** in this repo (`creatives_app.py`, pages in
`app/creatives/`, `make app-creatives` locally, port 8502) that shares the pipeline code, config and secrets with the
social dashboard but loads only the Meta ad feed, Klar attribution, tags and tests (`src/pipeline.py::build_creatives_bundle`).
It answers *which asset / hook works for which goal*. One view per **funnel stage**
(Prospecting / Retargeting, plus "Unknown stage" when a rule is missing); inside a view the **Meta optimisation
event** (conversion, value, landing page view, leads …) is the primary axis and the KPI the second. Source is the
`facebook__ads` Windsor pull (`src/ingest/windsor.py::ADS_FIELDS`, attribution window `7d_click,1d_view`) for spend
and delivery, and **Klar** for orders and revenue.

- **Excluded as organic / not creatives** (totals on the Data quality page and in the status line): Instagram post
  boosts (Organic vs Boosted owns them), page / post promotions (`page_promo_patterns`), ad sets optimised for
  profile visits / page likes / post engagement (`exclude_optimization_goals`) and ad names of other markets
  (`markets: [IT]`; the Vegavero ad account also carries DE boosts).
- **Asset** = the Meta ad name (the naming convention `[Prefix_]IT_Format_Product_Concept_Style_Version_YYYYMM[_Suffix]`
  identifies the creative; Meta's `creative_id` is per ad copy, so an asset keeps a list of creative ids for thumbnails).
  `src/transform/creatives.py::parse_ad_name` fills market, format, product (synonyms in `config/creatives.yaml`),
  concept, style, version, launch month and variant (`Test-Hand`, `Copy 2`, `_LP` / `_PDP`). Unparseable names keep
  their spend and show up on the Data quality page. The naming convention is not enforced yet; variants stay
  separate assets on purpose.
- **Funnel stage** per ad set from the rule chain in `config/creatives.yaml` (campaign `RTG` / `PROSPECTING`, ad set
  `website-visitors` / `broad`, targeting JSON with `custom_audiences`); `unknown` otherwise. The grain is
  asset × stage × optimisation goal × period: an asset is never summed across stages or goals.
- **Klar attribution** (`src/ingest/klar_marketing.py`): the Klar `marketing_flex` report grouped by
  `date, channel_name, campaign, content` has the Meta campaign and ad name per row, so its `orders`, `new_customers`,
  `net_revenue` and `gross_revenue` are joined to the feed on (date, campaign, ad name) and split across the ad sets of
  that day in proportion to Meta spend (totals preserved). ROAS = Klar gross revenue / Meta spend (Klar's own
  definition), CPA = Meta spend / Klar orders; rows without a Klar match fall back to Meta 7d-click / 1d-view
  (`roas_source` says which; `roas_meta` is always shown next to it). Drop JSON exports of the report (the shape the
  Klar MCP server / Public API return) into `KLAR_MARKETING_DIR` (default `data/raw/klar_marketing`) or point
  `KLAR_MARKETING_CSV` at a CSV export; the Klar HTTP client is still a stub, so `make refresh` does not pull it.
  `roas_source: meta` in the config switches the whole page to Meta attribution.
- **Metrics** recomputed from sums (rules in `config/metric_definitions.md`). **Verdict**: judged on the KPI of the
  row's optimisation goal (`kpi_by_goal`: conversion / value → ROAS, traffic / leads → CTR link …); target =
  account average of the current selection (pin a number under `targets:`); `Low data` below
  `min_spend_for_verdict` (€100).
- **Tags** (the "qualitative comment", filterable): `visual_subject`, `claim`, `offer`, `hook` from a controlled
  vocabulary, derived (1) from naming tokens (`tags:` synonyms), (2) by an LLM vision pass over the cached thumbnail +
  body + title (`src/transform/creative_tagging.py`, runs in `make refresh` once per new asset when `ANTHROPIC_API_KEY`
  is set, `pip install -e ".[tagging]"`, stored in `data/processed/creative_tags.parquet`), (3) from the **Creative
  tags** tab of the team input sheet, which always wins. `tag_source` is shown per asset.
- **Tests**: the **Tests** tab of the team input sheet (`test_id, test_name, variable, hypothesis, variant, asset_id,
  primary_kpi, learning`); the page ranks the variants on the primary KPI inside the period (all stages and goals
  summed) and flags a winner only with spend ≥ min on both leading variants and a ≥ 10 % lead.
- **Thumbnails**: `make refresh` caches `image_url` / `thumbnail_url` once per creative in `data/raw/creatives/`
  (Meta CDN URLs expire). Without the cache the page falls back to the live URL.
- **Data quality**: excluded spend by reason, unparseable ad names, ad sets with unknown stage, Klar coverage (spend
  without a Klar row, Klar rows without a feed row), assets without thumbnail / tags, and a spend reconciliation
  against an Ads Manager export dropped at `data/manual/meta_ads_export.csv`.

Windsor's history for the account starts when the connector was connected; for the June–October 2026 window of the
old Excel tracker the Ads Manager CSVs can be loaded once as a backfill (same columns as `ADS_FIELDS`).

## Periods and the team input sheet

- Every page shares the sidebar **period control**: granularity Week / Month / Quarter and a range (latest complete
  period, previous, last n, YTD, last 12 months, a specific period, custom dates). Quarter views are derived from
  the monthly frames (flows summed, followers = last month, ratios recomputed). The Overview tiles, Organic vs
  Boosted, Post performance and the Influencers page (ROAS / CPM per week, month or quarter) all follow it.
- **Team input sheet**: the Google Sheet *Social dashboard – manual inputs*
  (https://docs.google.com/spreadsheets/d/14OdxUcpwOqRKn_7QchrMr-7k8s79_ndtDCD1UvvIxoo/edit) is where the team
  types what no API delivers. Tabs: `Creator reach` (reach / views per creator post → `reach_source = input_sheet`,
  below Klar and the Klar sheet in priority), `Stories` (story views per account and day for days without an API
  pull), `TikTok weekly` (organic weekly numbers for vegavero/tiktok/DE, vegavero/tiktok/IT,
  vanatari/tiktok/INT …) and `Budget` (performance / awareness budget per brand and month). Row 1 is the header,
  row 2 help text, the example rows are skipped by the loader. Publish each tab to the web as CSV and list the
  links in `INPUT_SHEET_CSV_URLS`; `make refresh` caches them in `INPUT_SHEET_DIR` (default
  `data/raw/input_sheet`).

## Secrets / CI

Only via env (`.env`, see `.env.example`) or GitHub Actions secrets: `KLAR_API_KEY`, `KLAR_SHOP_ID`, `META_ACCESS_TOKEN`,
`IG_BUSINESS_ACCOUNT_IDS`, `WINDSOR_API_KEY`, optional `SOCIAL_XLSX_B64` (base64 workbook for the cron).
`refresh.yml` runs daily, caches `data/raw` + `data/processed`, and publishes the parquet files as release `data-latest`.

## Deploy (Streamlit Community Cloud)

Two apps from the same repo: the social dashboard (main file `streamlit_app.py`) and the Paid creatives app (main
file `creatives_app.py`). Each registers its pages via `st.navigation`; deps from `requirements.txt`, Python from
`.python-version`. The creatives app needs only `WINDSOR_API_KEY` (plus the optional `INPUT_SHEET_CSV_URLS`,
`ANTHROPIC_API_KEY` and the Klar marketing exports) and shows the fixture banner until the first refresh. In the app's **Secrets**, set the same keys as `.env.example` (TOML `KEY = "value"`);
Streamlit exposes them as environment variables. The workbook is not in the repo: either upload it as a base64 secret
and decode it at start-up, or run `make refresh` elsewhere and commit/publish `data/processed/*.parquet`
(the app prefers processed parquet over fixtures). Without either, the deployed app shows the fixture banner.

## Rebuilding the workbook from a Microsoft 365 connector dump

If the binary workbook is not reachable but a text dump of its worksheets is (tab-separated rows per sheet, as the
Microsoft 365 connector renders them), `scripts/rebuild_xlsx_from_dump.py DUMP.txt data/Social_Media.xlsx --only ...`
reconstructs a values-only workbook (numbers, percentages and `€` amounts converted back to numbers). Extra sheets can
be supplied as TSV with `--tsv "Creators=creators.tsv"`; keep the Creators address column out of that file.
